# Wren Browser UI Blueprint

هذه خريطة مرجعية لتصميم وتنفيذ واجهات Wren Browser. وجود ميزة هنا لا يعني أنها منفذة؛ نفصل الوضع الحالي عن الهدف.

## مبادئ التصميم
- الاتساق: كل شاشة تستخدم ألوانًا ومسافات وخطوطًا ومكونات مشتركة.
- الحالة مصدر الحقيقة: لا تعرض الواجهة نتيجة لم يؤكدها Android أو GeckoView.
- كل شاشة تغطي التحميل والمحتوى والفراغ والخطأ وانقطاع الاتصال ورفض الإذن والنجاح.
- RTL حقيقي، مع عكس العناصر الاتجاهية فقط.
- التخطيط يعتمد على المساحة المتاحة، لا اسم الجهاز.
- الأداء وإمكانية الوصول جزء من التصميم.

## الوضع الحالي
الموجود في rewrite-v2: المتصفح وشريط العنوان والتنقل والتبويبات، الصفحة الرئيسية، المفضلة والسجل والصفحات المحفوظة، القارئ، البحث داخل الصفحة، معلومات الموقع، المشاركة، الإعدادات، التنزيلات، أذونات المواقع والإشعارات، والثيم واللغة وRTL الأساسي.

المخطط وليس ادعاءً بالتنفيذ: نظام مكونات شامل، حالات موحدة، مركز خصوصية، تخصيص الصفحة الرئيسية، مجلدات وإدارة جماعية للمفضلة، مزامنة واستيراد/تصدير، تخطيط تابلت كامل، ومعاينة responsive. مانع الإعلانات مؤجل ولا يظهر كمفتاح عامل.

## خريطة التنقل
- المتصفح: الصفحة الرئيسية، صفحة ويب، شريط العنوان، قائمة الصفحة، التبويبات، البحث داخل الصفحة، معلومات الموقع، القارئ.
- المكتبة: المفضلة، السجل، الصفحات المحفوظة.
- التنزيلات.
- الإشعارات: مركز داخلي مستقبلي عند وجود قيمة فعلية.
- الإعدادات: المظهر، اللغة، الخصوصية والأذونات، التنزيلات، الصفحة الرئيسية، إمكانية الوصول، حول التطبيق.

## مواصفات الشاشات

### المتصفح
المناطق: هوية Wren/الموقع بهدوء في الأعلى، مؤشر تقدم، GeckoView، ورصيف زجاجي ثابت أسفل الشاشة من صفين. الصف الأول داخل الرصيف لحقل البحث/العنوان مع معلومات الموقع والتحديث؛ والصف الثاني للتنقل: رجوع، للأمام، الرئيسية، المفضلة، عداد التبويبات والقائمة، مع ظهور إجراء uBlock فقط عندما تكون الإضافة متاحة فعليًا. يبقى حقل البحث قريبًا من الإبهام في الهاتف، وتُعاد هندسة الترتيبات للمساحات العريضة والأفقية دون تغيير وظيفة الأزرار.
الحالات: صفحة البداية، تحميل، مكتمل، خطأ اتصال، رابط غير مدعوم، ملء الشاشة، تبويب متعطل، لوحة مفاتيح ظاهرة. كل زر يعكس حالة المحرك؛ التحديث يتحول إلى إيقاف أثناء التحميل.

#

### اتجاه Wren المعتمد (2026-11-08)
- المرجع السلوكي هو أنماط Chrome وSafari المألوفة، مع تنفيذ بصري ووظيفي مستقل خاص بـWren.
- شريط البحث والعنوان في الأسفل افتراضيًا على الهاتف، داخل سطح Glass شفاف ذي حدود وتباين واضحين.
- لا ننسخ شعارات أو أصولًا أو شيفرات مملوكة للمتصفحات المرجعية.
- على Android 8–11 يكون Glass قائمًا على الشفافية والحدود والطبقات؛ لا يعتمد التشغيل على تأثير blur غير مدعوم.
- هوية الطائر وألوانها تُستخدم على الصفحة الرئيسية وأيقونة التطبيق، مع عدم تحريف الشعار بين الفاتح والداكن.

## الصفحة الرئيسية
شعار مختصر، حقل بحث، اختصارات قابلة للتعديل، أقسام اختيارية للحديث والمحفوظ. الحالات: أول تشغيل، فارغة، بيانات، تحميل، خطأ قراءة. لا تعرض بيانات خاصة خلافًا لإعدادات الخصوصية.

### شريط العنوان
حقل إدخال، مسح، اقتراحات بحث/سجل/مفضلة، تنفيذ. تحقق من النص عبر NavigationInput، وادعم العربية والنطاقات الدولية. لا تقرأ الحافظة أو ترسلها تلقائيًا.

### التبويبات
بطاقات بعناوين ونطاقات، إغلاق، تبويب جديد، عداد وحد 20. الحالات: صفر، واحد، متعدد، الحد الأقصى، متعطل، مستعاد ولم تفتح جلسته. افتح جلسة الخلفية عند اختيارها فقط، ولا تعرض لقطة قديمة كأنها مباشرة. على الهاتف قائمة/شبكة؛ على المساحة الواسعة شبكة أعمدة.

### القائمة
تجمع إجراءات الصفحة (مفضلة، مشاركة، بحث، قارئ، معلومات الموقع)، التنقل والتبويبات، المكتبة والتنزيلات والإعدادات. تجنب تكرار الأزرار الظاهرة بلا داعٍ.

### المكتبة
المفضلة: الاسم والنطاق والفتح والتعديل والحذف؛ المجلدات لاحقًا. السجل: مجموعات زمنية وبحث وحذف عنصر أو فترة. الصفحات المحفوظة: الاسم والتاريخ والفتح والحذف. الحالات: تحميل، فارغ، لا نتائج، خطأ قراءة، تحديد متعدد، تأكيد حذف.

### التنزيلات
اعرض الاسم والحجم والحالة والتقدم والمصدر وسبب الفشل عند توفره. الحالات: انتظار، جارٍ، متوقف، مكتمل، فاشل، غير معروف، مفقود، فشل استعلام النظام. اعرض فقط الأفعال التي يدعمها DownloadManager؛ لا تدّعِ دعم POST أو الرؤوس المحمية أو الاستئناف غير المضمون.

### معلومات الموقع
الأصل الحالي، معلومات أمان موثوقة، الأذونات حسب النوع. حالات الإذن: سؤال، سماح، حظر، أو غير قابل للإلغاء. افصل دائمًا بين إذن Android وإذن الموقع؛ موافقة أحدهما لا تعني الآخر.

### القارئ والبحث
القارئ: عنوان ومصدر ومحتوى وحالات استخراج ناجح/جارٍ/فاشل/غير مدعوم. البحث داخل الصفحة: حقل، سابق/التالي، عداد إن توفر، إغلاق، ولا نتائج. لا تحجب لوحة المفاتيح النتائج.

### الإعدادات والإشعارات
الإعدادات مجموعات قصيرة: المظهر، اللغة، الصفحة الرئيسية، الخصوصية والأذونات، التنزيلات، إمكانية الوصول، حول التطبيق. كل خيار يشرح أثره ويعرض فشل الحفظ أو رفض الإذن. مركز الإشعارات الداخلي لا ينفذ إلا إذا أضاف قيمة واضحة فوق إشعارات Android.

## التكيف حسب النافذة ونوع التفاعل
- الهاتف بعرض Compact أقل من 600dp: شريط بحث/عنوان سفلي افتراضيًا، ويمكن للمستخدم نقله للأعلى. لا يغطي لوحة المفاتيح ولا يلتهم ارتفاع الصفحة في الوضع الأفقي.
- Medium من 600 إلى أقل من 840dp: استغلال مساحة التابلت دون تكبير عناصر الهاتف؛ تخطيط تبويبات أوسع وإمكانية لوحة جانبية عند ملاءمتها.
- Expanded من 840dp فما فوق: شريط علوي وتبويبات/لوحة جانبية أو تقسيم للمكتبة عند الحاجة، مع حد أقصى لعرض النص.
- نافذة أفقية قصيرة، split-screen أو نافذة خارجية: القرار حسب حدود النافذة الحالية لا طراز الجهاز. يجب حفظ الحالة أثناء تغيير الحجم.
- Foldables: مراقبة وضعية المفصل، وعدم وضع حقل أو زر مهم فوق منطقة فصل الشاشة.
- Android TV / Google TV: شاشة منفصلة بواجهات كبيرة، D-pad، لوحة كتابة مناسبة، ومؤشر Focus واضح لكل عنصر. لا تستخدم شريط الهاتف السفلي أو اللمس كوسيلة أساسية.
- Samsung Tizen وLG webOS ليستا Android؛ تحتاجان عملاء منفصلين مستقبلًا.

## التكيف البصري والأداء
مادة Glass ليست شرطًا لتشغيل المتصفح. يختار `AdaptivePresentationPolicy` بين blur حقيقي مدعوم ومقاس، أو زجاج ملوّن شفاف دون blur، أو أسطح matte/عالية التباين. تسبق إعدادات الوصول تفضيل المظهر، وتسبق قدرات API أي محاولة تشغيل تأثير. تغيير المادة لا يغير ترتيب الأزرار أو وظائفها ولا يعرض تحذيرًا للمستخدم. استخدم `JankStats` والـMacrobenchmark وPerfetto لقياس الأداء؛ لا تجرِ اختبارات ضغط مستمرة في الاستخدام العادي.

التفاصيل والقرارات والمراجع في `docs/WREN_ADAPTIVE_UX_RESEARCH_2026-11-08.md`.

## Design Tokens
الألوان بأدوار semantic: canvas، surface، elevated، field، textPrimary، textSecondary، accent، border، divider، success، warning، danger، info، selected، disabled، focus. يجب تكافؤ التباين بين الفاتح والداكن.
- شبكة المسافات أساسها 4dp؛ الشائع 4/8/12/16/20/24/32dp.
- هدف اللمس 48dp على الأقل.
- مستويات النص: Display، Title، Body، Label، Caption.
- خط النظام افتراضيًا مع اختبار تشكيل العربية والنص المختلط.
- عائلة أيقونات واحدة؛ نعكس الاتجاهية فقط.
- الحركة قصيرة وهادئة.
القيم النهائية تُقارن بملفات Figma قبل استبدال المقاسات أو الألوان.

## التخطيط التكيفي
Compact: عمود واحد وشريط سفلي. Medium: شبكة تبويبات ومساحات أوسع. Expanded: لوحة جانبية عند فائدتها ومحتوى محدود العرض. Landscape: تقليل استهلاك الارتفاع. تقسيم الشاشة: القياس حسب المساحة الفعلية. اختبر 320dp و360dp و393dp والهاتف الصغير والتابلت والأفقي وتكبير الخط.

## نموذج الحالة والتنفيذ
كل شاشة تملك State immutable وActions وReducer/Controller وEffects لعمليات Android/GeckoView/التخزين. الواجهة ترسم الحالة ولا تخترع نتائج. لا تحفظ GeckoSession في حالة UI أو التخزين الدائم. MainActivity مضيف رشيق؛ Design System للمظهر فقط؛ UI لا تقرأ SharedPreferences مباشرة؛ لا تضف طبقات أو Modules شكلية.

## الوصول والتوطين
وصف TalkBack لكل زر، ترتيب تركيز منطقي، تكبير خط دون قص، تباين واضح، عدم الاعتماد على اللون وحده، العربية والإنجليزية واتجاه مستقل للنص المختلط مع URL، وصيغ محلية للتاريخ والوقت والأرقام.

## بوابة قبول الشاشة
- تستخدم Tokens ومكونات مشتركة.
- كل زر يعمل أو معطل مع سبب.
- حالات التحميل/الفراغ/الخطأ/النجاح/رفض الإذن مكتملة حسب الحاجة.
- RTL صحيح، وTalkBack والتباين وتكبير الخط مدعومة.
- تخطيط Compact/Medium/Expanded وأفقي.
- لا تحميل أو رسم ثقيل بلا داعٍ.
- لا حالة أو إذن غير مؤكد يظهر كحقيقة.
- اختبارات Unit وUI/Instrumented حسب الحاجة.
- تحديث الخريطة عند تغيير التنقل أو المكونات.

## خطة التنفيذ
1. ربط كل شاشة بملف التنفيذ ومقارنة Figma.
2. استخراج tokens مركزية وبناء المكونات المتكررة.
3. تحسين Browser chrome وHome وTab Switcher.
4. تحسين Menu وSite Info وFind in Page.
5. تحسين Library وDownloads وReader.
6. تحسين Settings وPermission prompts.
7. تخطيطات تكيفية وRTL والوصول وحالات الأخطاء.
8. اختبارات Android 10 وما بعده وARM32/ARM64.
9. توسعات المفضلة والخصوصية والصفحة الرئيسية بعد تحديد عقودها واختبارها.

## سجل التغيير
لكل تعديل كبير نسجل التاريخ وcommit والشاشات المتأثرة والسبب والحالات الجديدة والاختبارات ونتيجتها وما لم يُختبر على جهاز فعلي.

**تعريف الاكتمال:** لا تكتمل الشاشة لأنها جميلة فقط؛ تكتمل عندما تعمل تفاعلاتها وحالاتها وإمكانية الوصول والتكيف والاختبارات.
