# BrowseX security integrations

## Phishing and malicious-site protection

The browser runtime enables GeckoView Content Blocking Safe Browsing with the engine's default unsafe-site categories. This is engine-level protection, not a hand-maintained URL list. Coverage and freshness depend on GeckoView's provider configuration, network access, and device/runtime; do not claim every phishing URL is detected. Tracking protection remains separate and is not a full ad blocker.

## Saved passwords and in-browser autofill

BrowseX uses GeckoView's native Autocomplete storage delegate and login prompts; it does not scrape forms with injected JavaScript. Stored credentials are encrypted with AES-GCM using a non-exportable Android Keystore key and kept in app-private preferences. Only HTTPS origins are accepted, form-action origins must match, and lookups require an exact origin match. Credential access is locked by default. The user must authenticate in the password manager to unlock a 60-second autofill window; one exact matching login may then autofill on reload, while multiple candidates require a selection prompt and fresh authentication. The app locks the window when it leaves the foreground. Any open private tab blocks credential fetch and save, and private sessions reject selection prompts. The manager exposes only usernames/origins before authentication; reveal, copy and delete require authentication.

A separate Android AutofillService is registered as an optional provider on Android 8+. The user must choose BrowseX in Android Autofill settings. For external web forms the service only prepares an authentication-required response; the internal Activity then requires device authentication and explicit selection from saved credentials whose canonical HTTPS origin matches exactly. It does not decrypt passwords in the Service, save credentials from other apps, fill HTTP forms, or provide passkeys. The AES-GCM key is now generated with Android Keystore user-authentication enforcement and a 60-second authentication validity window: API 30+ accepts strong biometrics or device credentials, while API 26–29 uses the platform's timed user-authentication authorization and biometric-enrollment invalidation. Save, lookup, reveal, copy and delete paths require a recent successful system authentication; GeckoView lookup can trigger authentication when the user focuses a login form. Existing v1 vault contents are re-encrypted under the authentication-bound v2 key after successful authentication, and the legacy key is removed only after the new ciphertext is committed. This does not protect a device while the authorization window is active, a compromised app process, or a rooted/compromised OS. Credentials are not synced or exported. Credential capture from other apps is disabled; Android-wide Autofill is fill-only in this release.

## Android permissions

Gecko media/location permission requests are scoped to the active GeckoSession and coordinated by BrowserAndroidPermissionCoordinator over BrowserAndroidPermissionQueue. Android notification permission requests use BrowserNotificationPermissionCoordinator, which coalesces concurrent callbacks and handles pre-Android-13 behavior separately. Activity Result launchers remain Activity-owned; coordinators own ordering, cancellation, stale-session rejection, and callback completion.
